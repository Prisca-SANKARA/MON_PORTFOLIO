Les 4 nœuds du workflow
🔗
1 — Webhook (Trigger)
Point d'entrée du workflow. Écoute les requêtes POST sur `/fasoartisans-inscription`. Reçoit les données JSON du formulaire et déclenche la chaîne automatiquement.
HTTP POST · JSON
🗄️
2 — Supabase (Create a row)
Sauvegarde les données de l'artisan dans la table `artisans` de Supabase PostgreSQL. Utilise la service_role key pour bypass le RLS et garantir l'écriture.
PostgreSQL · REST API
📧
3 — Email artisan (SMTP)
Envoie un email HTML personnalisé à l'artisan. Utilise les données du webhook pour personnaliser le contenu : nom, métier, ville. Template aux couleurs FasoArtisans.
SMTP Gmail · HTML email
🔔
4 — Notification admin (SMTP)
Envoie une notification à l'administrateur avec toutes les infos de l'artisan inscrit. Permet un suivi en temps réel sans avoir à consulter Supabase manuellement.
SMTP Gmail · Tableau HTML

Décisions techniques
🔗
n8n plutôt qu'un backend custom
Construire un backend Node.js pour envoyer des emails et sauvegarder en DB aurait pris 2-3 jours. n8n le fait en quelques heures avec une interface visuelle. Pour un MVP d'automatisation, c'est le bon outil — le code custom vient après la validation.
🐳
Docker pour exécuter n8n
n8n via Docker isole complètement l'environnement — pas de conflits de dépendances Node.js, facile à supprimer, et le volume `n8n_data` persiste les workflows entre les redémarrages. C'est exactement comment n8n est déployé en production.
📧
SMTP plutôt que Gmail OAuth2
Gmail OAuth2 nécessite de créer une app Google Cloud, activer l'API Gmail et configurer les URIs de redirection — 20 minutes de configuration pour un usage local. SMTP avec un mot de passe d'application Google est opérationnel en 2 minutes.
🛡️
Try/catch sur l'appel webhook côté formulaire
Si n8n n'est pas lancé, le formulaire continue à fonctionner — les données sont sauvegardées en localStorage et l'utilisateur voit le succès. Ne jamais bloquer l'utilisateur à cause d'un service externe.
Défis rencontrés
Commande curl multi-lignes incompatible Windows CMD
La syntaxe `\` pour les commandes multi-lignes ne fonctionne pas sur Windows CMD. Les arguments étaient interprétés comme des commandes séparées.
✅ Résolution : tout mettre sur une seule ligne sans retour chariot
Container n8n supprimé après extinction PC
Le flag `--rm` supprime automatiquement le container à l'arrêt. Après extinction du PC, n8n n'existait plus et `docker start n8n` échouait.
✅ Résolution : utiliser `-d` au lieu de `-it --rm` pour un container persistant
Alerte sécurité Supabase — table sans RLS
Supabase a détecté que la table `artisans` était accessible publiquement sans Row Level Security — n'importe qui avec l'URL pouvait lire/modifier les données.
✅ Résolution : activation RLS + policy permissive pour la service_role key
Ce que j'ai appris
1
n8n est un outil de productivité redoutable pour les MVPs. Ce qui prendrait 2 jours en code custom se fait en quelques heures avec une interface visuelle et des connecteurs prêts à l'emploi.
2
Les volumes Docker sont essentiels pour persister les données entre les redémarrages. Sans `n8n_data`, tout le workflow aurait été perdu à chaque extinction.
3
La résilience côté client — le try/catch autour de l'appel webhook — est une pratique indispensable. Un service externe ne doit jamais bloquer l'expérience utilisateur.
4
Activer RLS dès la création de la table — pas après. L'alerte Supabase aurait pu être évitée en ajoutant `enable row level security` dans le SQL initial.
