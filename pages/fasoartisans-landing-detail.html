Fonctionnalités
📝
Formulaire de pré-inscription
Collecte nom, métier, ville, téléphone avec validation en temps réel. Format téléphone normalisé automatiquement au standard burkinabè.
⚡
Onboarding automatisé via n8n
Chaque soumission déclenche un webhook n8n qui sauvegarde dans Supabase et envoie un email de bienvenue personnalisé automatiquement.
📊
Compteur de pré-inscrits dynamique
Le compteur se met à jour à chaque nouvelle inscription et persiste entre les sessions via localStorage. Crée un effet de preuve sociale.
📲
Partage WhatsApp intégré
Après inscription, un bouton WhatsApp génère un message pré-rédigé avec le lien de la page pour partager à ses collègues artisans.
👑
Système de niveaux freemium
4 niveaux présentés : Gratuit, Vérifié, Recommandé (3 000 FCFA/mois, max 3 places/ville), VIP Vitrine (25 000 FCFA/mois, 1 place/ville).
🎨
Design premium sans framework
100% HTML/CSS/JS vanilla — aucune dépendance externe. Animations CSS, scroll reveal, police Playfair Display pour une identité visuelle forte.
Décisions de conception
🎯
Valider avant de coder le backend
Plutôt que de construire toute la plateforme FasoArtisans (Next.js, Supabase, CinetPay, dashboard admin), on a d'abord créé une landing page pour mesurer l'intérêt réel. C'est la méthode Lean Startup — construire le minimum viable, mesurer, itérer.
📱
WhatsApp comme canal de viralité
Au Burkina Faso, WhatsApp est le réseau social dominant. Le bouton de partage post-inscription génère un message pré-rédigé qui cible directement les collègues artisans — le canal d'acquisition le plus naturel pour ce marché.
💰
Scarcité comme levier de conversion
Les plans Recommandé (max 3/ville) et VIP (1/ville) créent une urgence naturelle. Un artisan qui voit "Max 3 places par ville" comprend qu'attendre a un coût — c'est un levier psychologique puissant pour l'upselling futur.
🛡️
Résilience sans dépendance à n8n
Le formulaire fonctionne même si n8n est éteint — try/catch + localStorage garantissent que l'artisan voit toujours le succès et que la donnée est sauvegardée localement. L'UX ne dépend jamais d'un service externe.
Ce que j'ai appris
1
Valider avant de construire — une landing page de pré-inscription prend 1 jour à faire. Un backend complet prend des semaines. Les données de pré-inscription guident les vraies priorités.
2
Design sans framework CSS — CSS custom properties, animations keyframes et scroll reveal en vanilla JS suffisent pour un résultat premium. Zéro dépendance = zéro maintenance.
3
La validation téléphone burkinabè — les numéros BF ont plusieurs formats valides (+226, 00226, 8 chiffres directs). Une regex unique ne suffit pas — il faut tester chaque pattern séparément.
4
Connecter une landing page à un vrai pipeline (n8n + Supabase) dès le départ donne des données exploitables immédiatement — pas juste des chiffres localStorage fictifs.
