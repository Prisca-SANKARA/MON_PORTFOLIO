Décisions d'architecture
🗄️
Supabase plutôt qu'un backend custom
Supabase fournit PostgreSQL, Auth, Row Level Security et une API REST auto-générée. Pour un projet solo, ça élimine la complexité d'un backend Node/Express tout en restant production-ready.
🎨
Tailwind CSS plutôt qu'un fichier CSS global
Le co-location du style avec le composant élimine les conflits de classes CSS globales et le code mort. Chaque composant est auto-suffisant — on peut le déplacer ou le supprimer sans effets de bord.
🗺️
React Router v6 pour la navigation multi-pages
Le pattern Outlet permet un Layout partagé sans dupliquer le code sur chaque page. Le fichier _redirects Netlify gère le fallback pour les URLs directes.
🔒
Row Level Security pour l'isolation des données
Déplacer la sécurité au niveau de la base de données garantit que chaque utilisateur ne voit que ses données — même avec la clé publique exposée dans le bundle JS.
Défis techniques rencontrés
Tailwind v4 incompatible avec la commande init
La version 4 de Tailwind a supprimé la commande tailwindcss init sans documentation claire. Build échouait silencieusement.
✅ Résolution : downgrade vers Tailwind v3 avec npm install -D tailwindcss@3
Variables d'environnement non lues sur Netlify
Page blanche en production. Variable mal nommée VITE_SUPABASE_UR au lieu de VITE_SUPABASE_URL et le build utilisait un ancien snapshot.
✅ Résolution : correction du nom + redéploiement forcé
Erreur 404 sur les routes React Router en production
Accéder directement à /tasks retournait une 404 Netlify car le serveur cherchait un fichier physique inexistant.
✅ Résolution : fichier public/_redirects avec la règle /* /index.html 200
Ce que j'ai appris
1
La séparation des responsabilités — pages/composants/services — rend le code maintenable dès le départ, même sur un projet solo.
2
Row Level Security est plus robuste que le filtrage côté frontend. Sécuriser au niveau de la base de données élimine une catégorie entière de vulnérabilités.
3
Les variables Vite doivent commencer par VITE_ pour être exposées au bundle client — convention non-négociable du framework.
4
Le déploiement continu change le workflow — chaque push GitHub redéploie automatiquement sur Netlify. Adopter cette pratique dès le début est un gain de temps énorme.
